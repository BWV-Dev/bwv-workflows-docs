👤 Responsible: Project Leader

Protect every branch that can control a BWV Workflows run. Whoever can push to
one of these branches decides what the App runs with write access.

## Workflow Summary

1. [List every branch that controls a run](#1-list-every-branch-that-controls-a-run).
2. [Create a protection rule](#2-create-a-protection-rule).
3. [Enable the recommended settings](#3-enable-the-recommended-settings).
4. [Verify every configured branch](#4-verify-every-configured-branch).

## Step-by-Step Instructions

### 1. List every branch that controls a run

👤 Responsible: Project Leader

Protect both sets of branches:

1. Every base branch accepted by an `on.pull_request` trigger.
2. Every branch named by an `on.push.branches` trigger.

For example, this trigger requires protection for `main`, every matching
`release/*` branch, and `develop`:

```yaml
on:
  pull_request:
    base: [main, "release/*"]
  push:
    branches: [develop]
```

Repeat this review whenever `.bwv/workflows.yml` adds or changes a branch
pattern.

### 2. Create a protection rule

👤 Responsible: Project Leader

1. Open the repository on GitHub.
2. Select **Settings → Branches**.
3. Under **Branch protection rules**, select
   **Add classic branch protection rule**.
4. Enter the branch name or pattern, such as `main`, `develop`, or
   `release/*`.
5. Continue to the settings below before saving the rule.

![GitHub's form for adding a classic branch protection rule](/img/screenshots/protect-branches-new-rule.png)

_Enter the branch name pattern before enabling the required protections._

:::warning Check GitHub enforcement
For a private repository, GitHub enforces branch protection only when the
organization uses GitHub Team or Enterprise Cloud. If GitHub says the rules
will not be enforced, tell the BWV Workflows maintainers before enabling any
trigger.
:::

### 3. Enable the recommended settings

👤 Responsible: Project Leader

Enable these settings for each protected pattern:

- **Require a pull request before merging.**
- **Require approvals:** set at least one approval.
- **Dismiss stale pull request approvals when new commits are pushed.**
- **Require review from Code Owners** when the repository assigns owners to
  `.bwv/**` or `.claude/**`.
- **Require conversation resolution before merging.**
- **Do not allow bypassing the settings** for ordinary changes.
- Keep force pushes and branch deletion disabled.

Keep any existing required status checks. Add a `bwv/<workflow>` check only
after that workflow has run and its final name is known.

:::warning Protect patterns before enabling a trigger
Create protection for every matching branch, not only the default branch. A
push trigger for `develop` is not protected by a rule that covers only `main`.
:::

### 4. Verify every configured branch

👤 Responsible: Project Leader

1. Return to **Settings → Branches**.
2. Match each pull request base pattern in `.bwv/workflows.yml` to a protection
   rule.
3. Match each `on.push.branches` pattern to a protection rule.
4. Open a test pull request and confirm that GitHub requires the configured
   review before merging.

Continue with [Your first workflow](./first-workflow).
