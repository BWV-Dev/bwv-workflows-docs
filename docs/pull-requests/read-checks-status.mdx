## When you see this

BWV Workflows reports each workflow in two places on a pull request:

- A **check run** named `bwv/<workflow>` in the pull request checks.
- A **status comment** from **BWV Workflows** in the conversation.

Both show the same step table. Use the check run when you need the output from a failed step. Use the comment for a quick progress check and for actions such as **Retry**.

## Step-by-step

### 1. Find the latest result

1. **Dev or Com:** Open the pull request.
2. Select the status beside the latest commit, then open the check whose name starts with `bwv/`.
3. If several runs have the same name, open the latest one on the current commit.

The status comment in the **Conversation** tab is another view of the same workflow. The bot edits that comment as the run progresses instead of posting a new progress comment for every step.

### 2. Read the state

| What you see                                    | Meaning                                                                                       | What to do                                                             |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| ⏳ **running**                                  | The bot is working. The current step has ⏳ and later steps have ⬜.                          | Wait for the comment to update.                                        |
| ✅ **finished** or a passed check               | Every required step passed.                                                                   | Open and review any output pull request shown.                         |
| ❌ **failed**                                   | A step failed and no automatic attempt remains.                                               | Read the failed row and its output, fix the cause, then use **Retry**. |
| **finished**, with a closed output pull request | The steps passed, but publication is held because the earlier output pull request was closed. | Use **Recreate**, not **Retry**.                                       |
| **Waiting for quota**                           | The bot paused and will try automatically at the UTC time shown.                              | Wait. Do not request another run.                                      |
| **Waiting for a retry**                         | A temporary problem stopped the attempt. The bot still has an automatic attempt left.         | Wait for the stated UTC time.                                          |

### 3. Find the failed step output

1. **Dev or Com:** Open the failed `bwv/<workflow>` check run.
2. Find the row marked ❌. Read its **Step** and **Notes** cells first.
3. Expand **Output of _step name_** below the table.
4. Start with the last lines shown. They are the end of the output, not necessarily the complete output.

A passed check shows the completed table and, when one was created, a link to the output pull request.

### 4. Follow the run-again hint

A finished comment tells you how to run the workflow again:

```text
/bwv retry translate-docs
```

A failed comment shows a **Retry** checkbox instead. See [Running something again](/pull-requests/retry) before using it.

## What happens next

- While running, the bot updates the current step and its elapsed time.
- After success, review and merge the output pull request if the result is correct.
- After final failure, the check turns red and the comment offers a retry when that run is eligible.
- During an automatic wait, the check remains in progress. It passes or fails only after the later attempt finishes.

:::tip Which result should I trust?
Use the latest `bwv/…` check on the current commit. An older check describes an older version of the pull request.
:::

:::note Why is there no Retry checkbox?
The bot does not offer the box while work is running, while an automatic retry is pending, after success, or when **Recreate** is the correct action. A push-triggered run also has no pull request comment to hold a box.
:::

:::note Why is there no status comment?
Some repositories show the result only as a check run. Open the latest `bwv/<workflow>` check; it still contains the step table and result.
:::

:::caution The output is only the end
The collapsed block contains the final part of the failed step's output. If it does not explain the failure, ask the BWV Workflows maintainers to investigate.
:::
