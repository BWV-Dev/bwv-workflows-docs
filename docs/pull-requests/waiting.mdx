## When you see this

A yellow or in-progress BWV check is not always stuck. Read its title, summary, and tracker line before taking action. Most waits continue automatically.

## Step-by-step

### 1. Match the message

| What you see                                                     | What it means                                                                                 | What to do                             |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------- |
| **Waiting for quota**                                            | The current attempt used up the Claude quota.                                                 | Wait for the time shown.               |
| **Retrying automatically around HH:MM UTC**                      | The bot will try shortly after the reset time reported by Claude.                             | Wait. Do not tick **Retry**.           |
| ⏸️ **Stopped: Claude quota used up · retrying around HH:MM UTC** | A manual-run pass stopped. Work already published by earlier passes is kept.                  | Wait. The bot continues by itself.     |
| **Retrying automatically once the remaining workflows … finish** | Other workflows from the same request are still finishing before the retry time can be shown. | Wait. The bot will update the message. |
| **Waiting for a retry**                                          | A temporary problem stopped the attempt and another attempt remains.                          | Wait for the time shown.               |
| **running since …**                                              | Your Retry or Recreate request has started.                                                   | Wait for the result.                   |

“Around” is intentional; the next attempt may not start at the exact minute shown.

### 2. Open the check

1. **Dev or Com:** Open the pull request's **Checks** tab.
2. Find the latest `bwv/<workflow>` or `bwv/<workflow>/<group>` check.
3. Read the summary for the next retry time or the current step.
4. Return after the displayed time or after the current work finishes.

### 3. Wait through automatic infrastructure retries

A temporary infrastructure stop leaves the check in progress while automatic
attempts remain. This also applies when a `continueOnError` Claude process
fan-out ends with only infrastructure outcomes for its non-cancelled items.

The check run title is **Waiting for a retry: _reason_**. When the retry time is
known, the title adds **· retrying around HH:MM UTC**. Its summary starts with
this exact text:

```text
**Infrastructure error:** reason. The Claude CLI could not use the API, which is not a fault of this workflow. Retrying automatically around HH:MM UTC. This check stays in progress until the job ends.
```

Before the job has calculated the time, the retry sentence is exactly:

```text
Retrying automatically once the remaining workflows of this job finish.
```

The status comment uses the heading **⏳ BWV workflow waiting for a retry**.
Its **Error** block and ending around the normal step table are exactly:

```text
Infrastructure error: reason
```

```text
_Retrying automatically around HH:MM UTC. This comment updates when it does._
```

Ordinary retryable infrastructure stops use backoff delays of 30, 60, 120,
and 240 seconds across attempts.

If no automatic attempt remains, the check title is **Infrastructure error:
_reason_** and its summary says:

```text
**Infrastructure error:** reason. The Claude CLI could not use the API, which is not a fault of this workflow, and no retry is left. Ask whoever runs this App to look at its worker log.
```

The status comment heading becomes exactly **❌ BWV workflow failed** and
offers **Retry** when the run is attached to a pull request.

Funding, account, and throttle stops use their selected handling instead of
ordinary infrastructure backoff:

- A funding or billing stop uses the check title **Waiting for funding** and
  the status comment heading **⏸️ BWV workflow waiting for funding**. Its
  check says **There is no automatic retry time. Everything already published
  is kept.** Restore funding or switch authentication mode, then use **Retry**.
- An account, permission, or scope stop is terminal. The check uses
  **Infrastructure error: _reason_** with no automatic retry.
- An API throttle retries at its advertised delay when available, or a short
  backoff otherwise. It uses the same **Waiting for a retry: _reason_** check
  title.

The Claude subscription quota still wins over all of these. It keeps the
separate **Waiting for quota** title and quota reset schedule shown above.

## What happens next

The bot reuses the waiting check run for the next attempt. It updates the status comment or translation tracker when the work resumes. The check finishes green after success or red after the final failed attempt.

:::caution Do not spam Retry
Another Retry does not make quota or infrastructure time pass sooner. Send one request, then follow the same check.
:::

:::caution Do not close and reopen the pull request
Closing or reopening is not a recovery action. It can change which work is eligible and does not bypass a wait.
:::

:::note When should I ask the maintainers?
Ask the BWV Workflows maintainers when the displayed retry time has passed and the check has not updated after a reasonable delay, or when the final result says **Infrastructure error**. Include a link to the pull request and the affected `bwv/…` check.
:::
