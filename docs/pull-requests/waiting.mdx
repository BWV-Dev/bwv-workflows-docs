## When you see this

A yellow or in-progress BWV check is not always stuck. Read its title, summary, and the tracker request line before taking action. Most waiting states continue automatically.

## Step-by-step

### 1. Match the message

| What you see                                                     | What it means                                                                                 | What to do                             |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------- |
| **Waiting for quota**                                            | The current attempt reached a temporary quota limit.                                          | Wait for the automatic retry time.     |
| **Retrying automatically around HH:MM UTC**                      | The bot plans another attempt around the displayed UTC time.                                  | Convert from UTC if needed and wait.   |
| **Retrying automatically once the remaining workflows … finish** | Other workflows from the same request are still finishing before the retry time can be shown. | Wait. The bot will update the message. |
| **Waiting for a retry**                                          | A temporary infrastructure problem or interrupted attempt can still retry automatically.      | Wait for the automatic retry.          |
| **Queued: waits for the running `<workflow>` run**               | Your manual Retry or Recreate request was accepted behind a run already in progress.          | Wait for the running work to finish.   |
| **already covered by a run that is queued**                      | An existing queued run already includes the requested work.                                   | Do not request it again.               |
| **running since …**                                              | The queued request has started.                                                               | Wait for its check and tracker result. |

All displayed retry times are in **UTC**. “Around” is intentional; the next attempt may not start at the exact minute shown.

### 2. Open the queued check

1. **Dev or Com:** Open the pull request's **Checks** tab.
2. Find the queued `bwv/<workflow>` or `bwv/<workflow>/<group>` check.
3. Read its summary to see which running workflow it is waiting for.
4. Return after that workflow finishes. The same check changes from queued to in progress when the requested work starts.

### 3. Wait through automatic infrastructure retries

A temporary infrastructure stop leaves the check in progress while automatic attempts remain. The bot shows **Waiting for a retry** and, when known, the next UTC time. If no automatic attempt remains, the check fails and says **Infrastructure error**.

## What happens next

The bot reuses the waiting check run for the next attempt. It updates the status comment or translation tracker when the work resumes. The check finishes green after success or red after the final failed attempt.

:::caution Do not spam Retry
Another Retry does not make quota or infrastructure time pass sooner. It may only join work that is already waiting. Send one request, then follow the queued check.
:::

:::caution Do not close and reopen the pull request
Closing or reopening is not a recovery action. It can change which work is eligible and does not bypass a wait.
:::

:::note When should I ask the maintainers?
Ask the BWV Workflows maintainers when the displayed UTC retry time has passed and the check has not updated after a reasonable delay, when a queued check remains after the run it names has finished, or when the final result says **Infrastructure error**. Include a link to the pull request and the affected `bwv/…` check.
:::

:::note Why is there no Re-run button while queued?
The queued check is the acknowledgement that your request was accepted. It does not offer another Re-run action because the same work is already waiting.
:::
