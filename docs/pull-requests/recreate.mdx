## When you see this

Use **Recreate** when an output pull request was closed without merging and you want the bot to open a fresh pull request. Closing an output pull request is treated as a deliberate decision, so a normal run or retry does not reopen it.

You need **write** access to request a recreation.

## Step-by-step

### Option 1: Tick the Recreate box

1. **Dev or Com:** Return to the source or sync pull request that contains the tracker.
2. Expand **Actions**.
3. Tick **Recreate pull request `<group>`**.
4. Wait for the bot to untick the box and show that the recreation is queued or running.

For a workflow without groups, use the **Recreate pull request** box in its status comment.

### Option 2: Select Recreate PR

1. **Dev or Com:** Open the closed output pull request.
2. Open its `bwv/<workflow>/<group>` check run.
3. Select **Recreate PR**.

This button is available for a grouped output pull request. For a workflow without groups, use its comment box or the command below.

{/* TODO(screenshot): The GitHub Recreate PR button on a completed `bwv/translate-docs/source-pr-7` check run of a closed output pull request, tightly cropped with repository name and pull request number blurred */}

### Option 3: Add a command

On the source or sync pull request, comment:

```text
/bwv recreate source-pr-7
```

Replace `source-pr-7` with the group or workflow name shown in the tracker or status comment. The command checks the pull request's current state, so it can work even before a recently closed row has refreshed.

### Option 4: Recreate one manual loop batch

A finished manual-run hub lists closed, unmerged batches and folds its action boxes below the pass table. Tick **Recreate pull request `#N`**, or comment in the same issue or pull request conversation:

```text
/bwv recreate #9
```

The number identifies one published batch, not a workflow or source group. BWV Workflows accepts it only while that pull request is the newest eligible closed publication for its batch branch.

The replacement is recorded in the hub. The old row becomes `#9 (closed; replaced by #11)` and is never offered or loaded again. If the replacement later closes, recreate the newest eligible pull request instead of asking for #9 again.

## What happens next

The bot runs that work again and opens a new pull request from the same output branch. The old closed pull request stays closed. The tracker changes to the new pull request when publication succeeds.

For a manual loop batch, the next plan stops loading the numbered closed batch and recomputes the work from Git. The replacement may contain a different set of documents if repository state changed. Its pull request body records which old batch it supersedes so later runs do not load the old one again.

If the request is held behind a run already in progress, the bot shows it as queued and starts it after that run finishes.

:::caution Someone pushed to the output branch
The bot does not overwrite commits it does not recognize as its own. If the check says the output branch cannot be replaced, preserve any needed changes, then ask the repository's Project Leader to delete the branch or change the configured output branch name. Run **Recreate** again afterwards.
:::

:::note The outputs are already on the base branch
If all expected outputs were added or updated on the base branch after the source merge, there is nothing left to recreate. The tracker shows ✅ **already on** the base branch and no new pull request opens.
:::

:::note Only some outputs are on the base branch
Resolve the files named by **outputs partly on** the base branch. Then request **Recreate** again. The closed pull request remains in the tracker until the group is resolved or a replacement is published.
:::

:::note The button says it is out of date
The output pull request may have been reopened, merged, or already recreated. Return to the tracker and follow its current row instead of clicking again.
:::
