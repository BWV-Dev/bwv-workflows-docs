## When you see this

The **BWV source groups** comment is the translation tracker. It shows which source changes belong together and whether each group has an output pull request.

Before merge, the tracker is a preview. After merge, the bot edits the same comment with the authoritative result.

## Step-by-step

### 1. Check the tracker heading

- **planned** means preview only. No translation step has run, no branch has been pushed, and no output pull request has been opened.
- **running** means the merged pull request is being processed.
- **published** means the run has finished. Read every row because some groups may still need action.

<GitHubComment sample="translation-tracker-planned" author="BWV Workflows" />

:::caution Preview is advisory
Do not approve a source pull request only because the preview looks complete. The bot recalculates the groups when the pull request is merged. The published tracker is the authoritative result.
:::

<GitHubComment sample="translation-tracker-running" author="BWV Workflows" />

### 2. Read the columns

| Column           | What it means                                                                  |
| ---------------- | ------------------------------------------------------------------------------ |
| **Group**        | The name to use with `/bwv retry <group>` or `/bwv recreate <group>`.          |
| **Source**       | The source pull request or direct source change that the files came from.      |
| **Published PR** | The output pull request, or the current outcome if no pull request was opened. |
| **Files**        | The source files included in that group.                                       |

### 3. Read the outcome icon

| What you see                             | Meaning                                                                  | Next action                                               |
| ---------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------- |
| A pull request link such as `#8`         | Published successfully.                                                  | Review that output pull request.                          |
| ❌ **failed**                            | The named step failed.                                                   | Open **details**, fix the cause, then retry the group.    |
| ✅ **already on** the base branch        | All expected outputs were added or updated there after the source merge. | Nothing to publish or retry.                              |
| ⏸️ **outputs partly on** the base branch | Only some expected outputs were updated there.                           | Resolve the listed files on the base branch, then retry.  |
| ⚠️ **needs mapping**                     | The bot cannot choose which source pull request owns a source change.    | Add the command shown by the tracker.                     |
| `#8 (closed)`                            | The output pull request was closed without a merge.                      | Recreate it only if you want a fresh output pull request. |
| 🔄 **running**                           | That group is running now.                                               | Wait.                                                     |

### 4. Review the output pull requests

1. **Dev:** Open each pull request linked in **Published PR** and check the technical changes.
2. **Com:** Check the translated meaning, terminology, and completeness.
3. **Dev and Com:** Request corrections when needed. Changes may be pushed directly to the output pull request branch during review.
4. Merge an output pull request only after the normal project review is complete.

The bot creates the output pull requests. Dev and Com remain responsible for reviewing and merging them.

## What happens next

The tracker stays on the merged source pull request as the summary of all groups. If an output pull request is closed or reopened, the bot updates its row. A later retry of one group keeps the other groups' last displayed outcomes.

:::note Why did the groups change after merge?
The preview used the branches as they existed at that moment. The final tracker uses the merge result, so it can differ when either branch changed before merge.
:::

:::note Why is a published group not retryable?
The bot already published that group. Review the linked output pull request. If it was closed without merging and you need a fresh one, use [Recreating a closed pull request](/pull-requests/recreate).
:::

:::tip Where are the action boxes?
Expand the **Actions** section below a finished tracker. It appears only when at least one group can be retried or recreated.
:::

:::note What if a tracker row is briefly out of date?
The tracker shows the last result the bot displayed. Before recreating an output pull request, the bot checks whether that pull request is still closed and unmerged. It will not create another one from a stale row.
:::
