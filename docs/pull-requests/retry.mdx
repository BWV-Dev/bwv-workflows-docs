👤 Responsible: Dev & Com

## When you see this

Use a retry after you have fixed the reason a workflow or translation group failed. You need **write** access to the repository to request one.

Choose one of three ways: tick the offered box, select **Re-run** on one check run, or comment with `/bwv retry`.

## Step-by-step

### Option 1: Tick Retry

1. **Dev or Com:** Open the BWV Workflows status comment or translation tracker.
2. For a tracker, expand **Actions**.
3. Tick the **Retry** box for the failed workflow or group.
4. Wait for the bot to untick the box and show a queued or running line.

### Option 2: Select Re-run on one check run

1. **Dev or Com:** Open the failed check named `bwv/<workflow>` or `bwv/<workflow>/<group>`.
2. Open the check run menu.
3. Select **Re-run** for that check run.

For a grouped workflow, the workflow check retries the groups the tracker still offers. A group check retries only that group.

{/* TODO(screenshot): The GitHub Re-run button on a failed `bwv/translate-docs/source-pr-7` check run, tightly cropped with repository name and pull request number blurred */}

### Option 3: Add a pull request comment

Comment on the pull request with one of these commands:

```text
/bwv retry
```

This requests everything currently eligible to retry.

```text
/bwv retry translate-docs
```

This requests one workflow. Replace `translate-docs` with the exact workflow or group name shown by the check or tracker.

The bot adds a 👍 reaction after it has accepted the command, then answers with its result in a comment.

{/* TODO(screenshot): A `/bwv retry source-pr-7` pull request comment with the accepted 👍 reaction from BWV Workflows, with repository name, avatars, and pull request number blurred */}

See the [/bwv command reference](/reference/commands) for the complete generated list.

### Read the bot's answer

| Answer                                      | Meaning                                                               |
| ------------------------------------------- | --------------------------------------------------------------------- |
| **queued**                                  | The request was accepted.                                             |
| **after the run in progress finishes**      | The request is held behind the current run and will follow it.        |
| **after the work already waiting**          | Another request is already ahead of this one.                         |
| **already covered by a run that is queued** | The queued work already includes your request. Do not ask again.      |
| **running since …**                         | The requested retry has started.                                      |
| **Nothing to retry yet: … is running now**  | That exact workflow or group is already running. Wait for its result. |

If you make a typo or use an unknown `/bwv` command, the bot runs nothing and replies with the supported commands:

## What happens next

The bot uses the latest version of an open pull request when the retry starts. For a merged pull request, it retries work from that merge. The status comment, tracker, and check run update as the request waits, starts, and finishes.

:::caution Do not retry a published group
A group with an output pull request has already published. The bot refuses `/bwv retry <group>` for it. Review the existing pull request, or use **Recreate** if it was closed without merging.
:::

:::note Can I use Re-run all checks?
Use the **Re-run** action for the specific `bwv/…` check, a Retry box, or `/bwv retry`. A whole-suite **Re-run all checks** action is not a reliable way to request the intended BWV work.
:::

:::note Why did my request not start immediately?
Only one run of the same work proceeds at a time. The bot holds an eligible request behind the running work and shows that wait in the tracker or a queued check run.
:::
