## When you see this

Use a retry after you have fixed the reason a workflow or translation group failed. Choose one of two ways: tick the offered box or comment with `/bwv retry`.

A manual loop hub can also offer Retry after its last completed pass records a true `loop.retryWhen` result, or after the engine stops with a known backlog. The same rule applies: use the offered action only after the underlying problem is fixed.

## Step-by-step

### Option 1: Tick Retry

1. **Dev or Com:** Open the BWV Workflows status comment or translation tracker.
2. For a tracker, expand **Actions**.
3. Tick the **Retry** box for the failed workflow or group.
4. The bot unticks the box and shows that it accepted the request. Wait for the line to change to **running**.

### Option 2: Add a pull request comment

Comment on the pull request with one of these commands:

```text
/bwv retry
```

This requests everything currently eligible to retry.

```text
/bwv retry translate-docs
```

This requests one workflow. Replace `translate-docs` with the exact workflow or group name shown by the check or tracker.

The bot adds a 👍 reaction after it has accepted the command, then answers with its result in a comment.

See the [/bwv command reference](/reference/commands) for the complete generated list.

### Read the bot's answer

The bot first confirms that it accepted the request, then shows **running since …** when the work starts. If the same work is already running or already requested, do not comment again. Wait for the current result.

If you make a typo or use an unknown `/bwv` command, the bot runs nothing and replies with the supported commands:

## What happens next

The bot uses the latest version of an open pull request when the retry starts. For a merged pull request, it retries work from that merge. The status comment, tracker, and check run update as the request is accepted, starts, and finishes.

For a manual workflow, the retry stays in the existing hub for that workflow and branch. Its new attempt rows appear with the current run, while earlier request histories remain folded. A later false `loop.retryWhen` result clears earlier retry evidence.

:::caution Do not retry a published group
A group with an output pull request has already published. The bot refuses `/bwv retry <group>` for it. Review the existing pull request, or use **Recreate** if it was closed without merging.
:::

:::note Why did my request not start immediately?
Only one run of the same work proceeds at a time. Wait for the current run; the tracker updates when your request starts.
:::
