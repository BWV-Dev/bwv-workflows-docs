👤 Responsible: Project Leader

Start with the latest `bwv/…` check on the current commit. Read its summary and the BWV Workflows comment before requesting another run.

## Nothing ran

Check these causes in order:

1. **The workflow did not match.** Confirm the pull request action, base branch, head branch, and changed paths against the workflow trigger. Every configured filter must match. See [Triggers](./configuring/triggers).
2. **The configuration exists only on the head branch.** Pull request workflows use `.bwv/workflows.yml` from the current base branch. Merge the configuration into the base before testing it. See [Your first workflow](./getting-started/first-workflow#2-merge-the-configuration-into-the-base-branch).
3. **The pull request comes from a fork.** BWV Workflows does not run the workflow steps for fork pull requests. Move the work to a branch in the repository when it is trusted to run.
4. **The App is not installed for the repository.** Ask the BWV Workflows maintainers to confirm installation and repository access. See [Onboard your repository](./getting-started/onboard-repository).

## `bwv/config` is red

Open the `bwv/config` check and read the validation message. Fix `.bwv/workflows.yml` or the referenced recipe on the base branch; changing only the pull request head does not change the trusted configuration for that pull request.

When a remote recipe is not found, the message shows the path BWV Workflows
tried in the source repository. For example, a missing
`BWV-Dev/bwv-workflows-recipes/translation/missing@translation/v1` reference
reports `recipes/translation/missing.yml`. Check that this file exists at the
named ref.

Use [Editor autocomplete](./getting-started/editor-autocomplete) to catch schema errors while editing, then follow [Your first workflow](./getting-started/first-workflow) to merge and test the fix.

## A step failed with permission denied

Open the failed step and identify the tool or path it tried to use. Check the step or recipe's `disallowedTools` first; a matching deny rule wins. Change the tool rules only when that access is intended, then retry the failed work.

See [Steps: claude, shell, uses](./configuring/steps) for step permissions. After fixing the cause, send Dev & Com to [Working on a pull request](./pull-requests) for the retry action.

## When Dev & Com report a problem

Start with the result they see, not with a configuration change. Use [When Dev & Com report a problem](./troubleshooting/dev-com-reports) to diagnose check-run actions, accepted requests that are still waiting, closed output pull requests, merge skips, source mapping, quota waits, and infrastructure retries.

Send Dev & Com back to [Working on a pull request](./pull-requests) after you have resolved the cause or identified the correct action.

## Editor autocomplete does not work

Connect to the company network, then reopen the YAML file and check the configured schema URL. If the URL or access still fails, ask the BWV Workflows maintainers for the current `<engine-host>` value.

See [Editor autocomplete](./getting-started/editor-autocomplete) for the complete setup and verification steps.

## Asking the BWV Workflows maintainers for help

Include these details:

- The repository, such as `acme/web-app`.
- A link to the affected pull request.
- The exact workflow name from the `bwv/<workflow>` check.
- The small footer line at the bottom of the check run summary: `Job … · attempt n/max · delivery …`.

The footer identifies the run in the engine logs. Copy the complete line without changing its job, attempt, or delivery values.

When the problem comes from a shared recipe, you can also open an issue or a pull request in `BWV-Dev/bwv-workflows-recipes`. See [Report a problem or contribute a fix](/recipes#report-a-problem-or-contribute-a-fix).
