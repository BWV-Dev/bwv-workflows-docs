👤 Responsible: Project Leader

Use an official recipe when its trigger and output match the process in your repository. Shared recipes come only from `BWV-Dev/bwv-workflows-recipes`; each catalog page shows the matching family tag.

| Recipe                                                                              | What it does                                                                                                                             | Trigger                                                                                                        | Who reviews the output                                                                       |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| [translation/grouped](/recipes/translation-grouped)                                 | Translates Japanese Markdown into Vietnamese, one source group per draft pull request, and keeps the reviewed translation cache aligned. | A merged sync pull request, a push to a translation branch, or a pull request that changes translation output. | Dev & Com review each translation pull request. BWV Workflows verifies its cache.            |
| [translation/backfill](/recipes/translation-backfill)                               | Translates documents that existed before the normal translation workflow was enabled, one manual batch pull request at a time.           | A person starts it with `/bwv run`.                                                                            | Dev & Com review each batch pull request.                                                    |
| [translation/sync-cache-completeness](/recipes/translation-sync-cache-completeness) | Finds reviewer edits, updates only the affected translation caches, and verifies that every edit was recorded.                           | The calling workflow decides. `translation/grouped` calls it after a push to a translation branch.             | BWV Workflows verifies the cache; Dev & Com continue reviewing the translation pull request. |
| [common/command-fanout](/recipes/common-command-fanout)                             | Runs one project skill or command for every item, with separate processes and bounded parallelism.                                       | The calling workflow decides.                                                                                  | The reviewers of the calling workflow review its output.                                     |

## Choose a recipe

1. **Project Leader:** Choose `translation/grouped` for the complete translation process. Do not add `translation/sync-cache-completeness` separately unless you are building your own translation workflow.
2. **Project Leader:** Add `translation/backfill` when documents already existed before the grouped translation process was enabled.
3. **Project Leader:** Choose `common/command-fanout` inside a project recipe when the same project command must run independently for several items.
4. **Project Leader:** Open the recipe page, check its prerequisites, and copy the complete `uses` line, including its family tag.

:::tip
Start with each recipe's default toolkit. Override a toolkit only when your repository already has skills or scripts that meet the complete toolkit contract.
:::

## Report a problem or contribute a fix

👤 Responsible: anyone who uses a shared recipe

`BWV-Dev/bwv-workflows-recipes` accepts issues and pull requests. When a shared recipe misbehaves in your project — wrong or broken output, a check that fails for no visible reason, a rule a skill does not follow, an input you need but cannot set — report it there, or fix it yourself. If you cannot open the repository, ask the BWV Workflows maintainers for access.

1. **Open an issue** with:
   - the complete `uses` line, including its family tag or pinned sha;
   - a link to the affected pull request and the exact `bwv/…` check;
   - the footer line of that check run summary, `Job … · attempt n/max · delivery …`;
   - what you expected and what happened instead.
2. **Open a pull request** when you know the fix: change the recipe, skill, or script together with its tests, and say in the description which behaviour changes for every project that uses the recipe. The maintainers review it and release it as a new family tag.

:::caution
The recipes repository is shared by every project. Do not paste customer documents or project content into an issue or pull request. Describe the problem, or reduce it to a small fictional example.
:::

Once a fix is released, projects on a moving tag such as `@translation/v1` receive it on their next run, and projects pinned to a sha receive it when they update the pin. A problem with checks, comments, retries, or triggers in general belongs to the engine, not to a recipe: [ask the BWV Workflows maintainers](/troubleshooting#asking-the-bwv-workflows-maintainers-for-help).
