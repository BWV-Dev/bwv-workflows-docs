👤 Phụ trách: Project Leader và Dev & Com

BWV Workflows là một GitHub App chạy công việc trong repository bằng Claude. Repository khai báo các công việc trong `.bwv/workflows.yml`. App báo cáo từng lần chạy trên GitHub và có thể mở một pull request (PR) chứa kết quả.

## Hướng dẫn từng bước

### 1. Kích hoạt workflow

👤 Phụ trách: Project Leader và Dev & Com

Project Leader chọn một hoặc cả hai điều kiện kích hoạt (trigger) trong `.bwv/workflows.yml`:

- **Pull request:** Chạy khi một pull request nhắm đến nhánh đích (base branch) đã cấu hình.
- **Push:** Chạy khi commit được đưa lên một nhánh đã cấu hình.

Workflow có thể lọc theo nhánh, hành động trên pull request và đường dẫn đã thay đổi. Xem [Điều kiện kích hoạt](../configuring/triggers) để biết các tùy chọn cấu hình.

### 2. Theo dõi lần chạy trên GitHub

👤 Phụ trách: Dev & Com

Mở pull request nguồn. Tìm các thông tin sau:

- Một check run tên `bwv/<workflow>` hiển thị từng bước và kết quả.
- Một comment trạng thái của **BWV Workflows** được cập nhật tại chỗ khi lần chạy tiến triển.
- Nếu một bước thất bại, check run hiển thị lỗi ngắn và phần cuối nội dung trả về của bước.

<GitHubComment sample="status-running" author="BWV Workflows" />

Workflow do push kích hoạt báo cáo trên commit được push. Thông thường, workflow này không có pull request nguồn để đăng comment.

### 3. Xem lại PR kết quả

👤 Phụ trách: Dev & Com

Khi workflow được cấu hình để xuất bản thay đổi, BWV Workflows commit các thay đổi đó vào một nhánh mới rồi mở PR kết quả. Hãy review và merge pull request đó theo quy trình thông thường của repository.

Nếu workflow chỉ kiểm tra hoặc báo cáo thông tin, workflow có thể hoàn tất mà không tạo PR kết quả. Kết quả vẫn nằm trong check run.

#### Ví dụ: một thay đổi đi qua `acme/web-app`

1. Project Leader thêm workflow `review-docs` vào nhánh `main` của `acme/web-app`.
2. Một developer mở pull request thay đổi `docs/specs/login.md`.
3. BWV Workflows bắt đầu check `bwv/review-docs` và đăng một comment trạng thái.
4. Workflow đọc cấu hình đã được duyệt từ `main` và xử lý thay đổi được đề xuất trong tài liệu.
5. Check hoàn tất. BWV Workflows đặt liên kết đến PR kết quả trong comment trạng thái.
6. Nhóm review các thay đổi được tạo ra trước khi merge.
