## Hướng dẫn từng bước

### 1. Kích hoạt workflow đã cấu hình

👤 Phụ trách: Project Leader và Dev & Com

Một sự kiện GitHub phù hợp sẽ bắt đầu lần chạy:

- Pull request được mở, cập nhật, mở lại hoặc merge nếu hành động đó đã được cấu hình.
- Một push đến nhánh đã cấu hình.

BWV Workflows đọc `.bwv/workflows.yml`, so khớp nhánh và đường dẫn, rồi chọn các workflow cần chạy.

### 2. Đọc check run

👤 Phụ trách: Dev & Com

BWV Workflows tạo check tên `bwv/<workflow>` trên commit nguồn. Check hiển thị các bước đang xếp hàng, đang chạy, thành công và thất bại. Check cũng hiển thị lỗi cuối cùng khi một bước không thể hoàn tất.

Nếu cấu hình có lỗi, hãy tìm check `bwv/config`. Check này cho Project Leader biết nhánh đáng tin cậy nào đã cung cấp cấu hình không hợp lệ.

### 3. Theo dõi comment trạng thái

👤 Phụ trách: Dev & Com

Với lần chạy từ pull request, BWV Workflows đăng một comment trạng thái và chỉnh sửa comment đó khi các bước hoàn tất. Nhờ vậy, trạng thái mới nhất luôn nằm ở một chỗ. Project Leader có thể tắt comment này bằng `statusComment: false`; check run vẫn được tạo.

Lần chạy từ push thường chỉ báo cáo qua check run vì không có pull request nguồn.

### 4. Xem lại PR kết quả

👤 Phụ trách: Dev & Com

Nếu workflow tạo ra thay đổi và có cấu hình `onSuccess.createPullRequest`, BWV Workflows commit kết quả, push một nhánh và mở PR kết quả. Check và comment trạng thái đã hoàn tất sẽ đặt liên kết đến PR này.

Nếu workflow không tạo ra thay đổi hoặc không được cấu hình để mở pull request, lần chạy kết thúc sau khi báo cáo kết quả.

### 5. Biết nhánh nào điều khiển lần chạy

👤 Phụ trách: Project Leader

:::important Nhánh đích điều khiển nội dung workflow có thể thực thi
Với lần chạy từ pull request, BWV Workflows đọc `.bwv/workflows.yml`, skill và command trong `.claude/`, cùng các recipe cục bộ từ nhánh đích (base branch) của pull request. Cấu hình đó cũng chọn recipe chính thức dùng chung và tham chiếu `@v1` của recipe. Nhánh nguồn (head branch) của pull request chỉ cung cấp nội dung cần xử lý.

Với lần chạy từ push, nhánh được push vừa là nhánh đích vừa chứa nội dung cần xử lý.
:::

Quy tắc này có hai hệ quả:

1. Thay đổi với `.bwv/workflows.yml` trong pull request chỉ có hiệu lực sau khi được merge. Quy tắc này cũng áp dụng cho skill và command trong `.claude/`.
2. Workflow chạy khi pull request được merge sẽ dùng trạng thái của nhánh đích ngay trước lần merge đó. Cấu hình đi cùng pull request vừa merge chỉ có hiệu lực **từ lần merge tiếp theo**.

Merge thay đổi của workflow vào nhánh đích trước khi dùng workflow trong pull request thử nghiệm.
