## Hướng dẫn từng bước

### 1. Nhờ maintainers xác nhận quyền truy cập {#1-ask-the-maintainers-to-confirm-access}

👤 Phụ trách: Project Leader

Nhờ BWV Workflows maintainers xác nhận repository thứ hai hiển thị với cùng bản cài GitHub App của `acme/web-app`. App phải được cài cho cả hai repository trong bản cài đó. BWV Workflows không thử bản cài khác khi không thấy repository.

Dùng định dạng sau với hai tên giả trong yêu cầu:

```text
Target repository: acme/web-app
Context repository: acme/spec-library
```

Chờ xác nhận trước khi merge cấu hình workflow.

### 2. Khai báo repository và nơi đặt file {#2-declare-the-repository-and-destination}

👤 Phụ trách: Project Leader

Thêm một mục `context` vào workflow. Giá trị `submodule` là đường dẫn gitlink tương đối với repository. Commit được ghim của gitlink này nằm trong cây file của pull request. Giá trị `repo` là tên repository mà BWV Workflows được phép lấy.

```yaml title=".bwv/workflows.yml"
version: 1
workflows:
  - name: review-against-specs
    on:
      pull_request:
        types: [opened, synchronize, reopened]
        base: [main]
        paths: ["src/**", "specs"]
    context:
      - submodule: specs
        repo: acme/spec-library
        require: [published]
    steps:
      - name: Review the implementation
        claude:
          prompt: |
            Compare the pull request with the files below specs/published.
            Report contradictions without editing the repository.
          allowedTools: [Read, "Bash(git diff:*)"]
```

Liệt kê trong `require` từng thư mục mà bước thực sự đọc. Sau khi giải nén, mỗi đường dẫn trong danh sách phải chứa ít nhất một file thông thường. Nếu không, lần chạy sẽ thất bại trước khi bước bắt đầu.

### 3. Giữ tên repository đáng tin cậy {#3-keep-the-repository-name-trusted}

👤 Phụ trách: Project Leader

Merge cấu hình `context.repo` vào nhánh đích trước khi kiểm tra. Commit trên nhánh đích chỉ định repository thứ hai. Nhánh nguồn của pull request có thể cập nhật gitlink sang commit khác trong repository đó, nhưng không thể chọn repository khác.

Không có trường `ref` di động. Gitlink ghi lại đúng commit mà workflow đã review, nên pull request hiển thị thay đổi của giá trị ghim.

:::important Không clone submodule
BWV Workflows không chạy `git submodule`, khởi tạo submodule hay đọc `.gitmodules`. Nó đọc commit trong gitlink, lấy đúng kho lưu trữ của commit đó bằng App rồi giải nén tại `submodule`.
:::

### 4. Dùng các file đã giải nén {#4-use-the-unpacked-files}

👤 Phụ trách: Project Leader

Đọc repository thứ hai bên dưới đường dẫn `submodule` đã cấu hình. Trong ví dụ, bước đọc `specs/published`.

Hãy coi ngữ cảnh đã giải nén là đầu vào. Git bỏ qua các file đặt bên dưới gitlink, nên thay đổi ở đó không được đưa vào PR kết quả. Khi workflow cần xuất bản kết quả, hãy ghi file được tạo ra vào nơi khác trong `acme/web-app`.

Nếu không lấy được file, hãy xác nhận tên repository, commit đã ghim và việc repository hiển thị với cùng bản cài App. Nhờ BWV Workflows maintainers kiểm tra quyền truy cập của bản cài. Đừng thêm thông tin đăng nhập hoặc lệnh submodule vào workflow.
