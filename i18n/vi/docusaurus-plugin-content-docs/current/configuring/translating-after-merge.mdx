Hãy bắt đầu với [recipe translation/grouped](../recipes/translation-grouped) do BWV Workflows maintainers chăm sóc. Recipe này đã cấu hình sẵn cách gom nhóm, dịch, kiểm tra đầu ra và comment theo dõi (tracker) cho người review. Chỉ tự viết workflow theo nhóm khi repository cần quy trình khác.

`sourcePrGrouping` lấy tài liệu từ một pull request đồng bộ đã merge, lần theo pull request nguồn của từng tài liệu rồi chạy workflow một lần cho mỗi nhóm nguồn. Sau đó, mỗi nhóm có thể xuất bản một PR kết quả gọn, đúng trọng tâm.

## Hướng dẫn từng bước

### 1. Chọn file nguồn {#1-choose-the-source-files}

👤 Phụ trách: Project Leader

Đặt `sourcePrGrouping.paths` rõ ràng. Trường này là bắt buộc và không có giá trị mặc định. Một pull request đồng bộ có thể chứa tài liệu, code và cấu hình. Vì vậy, BWV Workflows không thể tự chọn an toàn những file thuộc công việc dịch.

Dùng cùng mẫu glob trong `on.pull_request.paths` khi workflow chỉ nên chạy cho các file đó. Hai trường có vai trò khác nhau:

- `on.pull_request.paths` quyết định workflow có khớp với pull request đã merge hay không.
- `sourcePrGrouping.paths` quyết định file nào đã thay đổi và không bị xóa sẽ trở thành nhóm nguồn.

Ví dụ sau gom các file Markdown trong `docs/specs` và xuất bản một pull request cho mỗi nhóm:

```yaml title=".bwv/workflows.yml"
version: 1
workflows:
  - name: translate-after-merge
    fetchDepth: 0
    on:
      pull_request:
        types: [closed]
        base: [main]
        head: [docs-sync]
        merged: true
        paths: ["docs/specs/**/*.md"]
    sourcePrGrouping:
      paths: ["docs/specs/**/*.md"]
      ignorePaths: ["docs/specs/templates/**"]
      sourceRoot: docs/specs
      requireOutputs:
        - "docs_vn/specs/${{ rel }}.vi.md"
        - "docs_vn/specs/${{ rel }}.vi.json"
      maxFilesPerGroup: 3
    steps:
      - name: Translate documents
        forEach: ${{ sourceGroup.files }}
        fanout: process
        maxParallel: 1
        claude:
          prompt: |
            Translate ${{ item }} into Vietnamese.
            Mirror its path below docs_vn/specs.
            Write both the .vi.md translation and its .vi.json cache.
          allowedTools: [Read, Write, Edit]
    onSuccess:
      createPullRequest:
        branch: "bwv/translate/sync-${{ sourceGroup.syncPr }}/${{ sourceGroup.id }}"
        title: "docs(vi): ${{ sourceGroup.id }}"
        draft: true
```

Đặt `maxFilesPerGroup` thành kích thước nhóm lớn nhất mà một PR kết quả nên chứa. Nhóm nguồn lớn hơn sẽ được tách thành các phần ổn định.

### 2. Khai báo mọi đầu ra bắt buộc {#2-declare-every-required-output}

👤 Phụ trách: Project Leader

Liệt kê trong `requireOutputs` mọi file mà một tài liệu nguồn phải tạo ra. BWV Workflows thay giá trị vào từng mẫu cho từng file nguồn. Nó chỉ xuất bản nhóm khi mọi file sau khi thay đều tồn tại. Hãy kiểm tra nội dung file trong một bước của workflow nếu chỉ kiểm tra sự tồn tại là chưa đủ.

Dùng `sourceRoot` cùng `${{ rel }}` cho cây nguồn lồng nhau. Ví dụ, hai nguồn sau vẫn tách biệt:

| Nguồn                         | `${{ rel }}`    | Bản dịch bắt buộc                   |
| ----------------------------- | --------------- | ----------------------------------- |
| `docs/specs/account/login.md` | `account/login` | `docs_vn/specs/account/login.vi.md` |
| `docs/specs/admin/login.md`   | `admin/login`   | `docs_vn/specs/admin/login.vi.md`   |

Tránh dùng `${{ name }}` cho tài liệu lồng nhau. Giá trị này chỉ chứa tên file, nên cả hai file trên đều trở thành `login` và cùng nhận một đầu ra. BWV Workflows từ chối nhóm khi các file nguồn trùng nhau trên mọi đầu ra đã khai báo.

:::important Giữ bước và bảng ánh xạ đầu ra khớp nhau
`requireOutputs` không tạo file. Hãy để các bước ghi đúng đường dẫn được khai báo ở đó. Thiếu đầu ra bắt buộc sẽ làm nhóm thất bại và ngăn việc xuất bản.
:::

### 3. Dùng một nhánh riêng cho mỗi nhóm {#3-give-every-group-its-own-branch}

👤 Phụ trách: Project Leader

Thêm `${{ sourceGroup.id }}` vào `onSuccess.createPullRequest.branch`. Mã định danh ổn định này tạo nhánh cố định cho từng nhóm và giúp lần chạy lại tìm thấy cùng PR kết quả. Workflow theo nhóm không có giá trị này là không hợp lệ, vì một nhóm có thể ghi đè nhánh của nhóm khác.

Repository tự chọn phần còn lại của không gian tên nhánh. Ví dụ cũng thêm `${{ sourceGroup.syncPr }}` để dễ phân biệt các pull request đồng bộ.

### 4. Hiểu giai đoạn bản xem trước và merge {#4-understand-preview-and-merge-phases}

👤 Phụ trách: Project Leader

Trước khi merge, BWV Workflows tự đăng tracker dự kiến. Bản xem trước gom nhóm theo nhánh đích và nhánh nguồn hiện tại, nhưng không chạy bước, push nhánh hay mở PR kết quả.

<GitHubComment sample="translation-tracker-planned" author="BWV Workflows" />

Sau khi pull request đồng bộ được merge, BWV Workflows tính lại các nhóm từ kết quả merge. Kết quả tại lúc merge là kết quả chính thức. Cùng một tracker chuyển từ **planned** (đã lên kế hoạch) sang **running** (đang chạy), rồi sang **published** (đã xuất bản).

Người review dùng tracker để mở PR kết quả, xem lỗi và yêu cầu chạy lại khi đủ điều kiện. Hãy hướng dẫn Dev & Com đọc [Làm việc với BWV Workflows trên PR](../pull-requests) thay vì ghi lại các thao tác đó trong file workflow.
