## Hướng dẫn từng bước

### 1. Cấu hình điều kiện kích hoạt từ pull request {#1-configure-a-pull-request-trigger}

👤 Phụ trách: Project Leader

Dùng `on.pull_request` khi công việc cần chạy theo các thay đổi được đề xuất cho nhánh đích (base branch):

```yaml title=".bwv/workflows.yml"
version: 1
workflows:
  - name: review-specs
    on:
      pull_request:
        types: [opened, synchronize, reopened, ready_for_review]
        base: [main, "release/*"]
        head: ["feature/*"]
        paths: ["docs/specs/**"]
        ignorePaths: ["docs/specs/archive/**"]
    steps:
      - name: Review the specification changes
        claude:
          prompt: |
            Review the changed files under docs/specs.
            Report inconsistencies without editing any file.
          allowedTools: [Read, Glob, "Bash(git diff:*)"]
```

Mọi bộ lọc đã cấu hình đều phải đạt:

| Trường        | Nội dung được khớp                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `types`       | Hành động GitHub: `opened`, `synchronize`, `reopened`, `ready_for_review` hoặc `closed`. Mặc định là `opened` và `synchronize`. |
| `base`        | Nhánh đích của pull request. Danh sách không rỗng này là bắt buộc.                                                              |
| `head`        | Nhánh nguồn. Bỏ qua trường này để nhận mọi nhánh nguồn không đến từ fork.                                                       |
| `merged`      | Pull request có trạng thái `closed` đã được merge hay chưa. Dùng cùng `types: [closed]`.                                        |
| `paths`       | Phải có ít nhất một file thay đổi khớp mẫu.                                                                                     |
| `ignorePaths` | Workflow được bỏ qua khi mọi file vốn khớp đều nằm trong danh sách bỏ qua.                                                      |

Các mục nhánh và đường dẫn là mẫu glob. Đường dẫn là tương đối với repository và gồm cả dotfile khi mẫu glob khớp.

Dùng điều kiện kích hoạt khi đóng và đã merge cho công việc chỉ được bắt đầu sau khi pull request được đưa vào nhánh:

```yaml title=".bwv/workflows.yml"
version: 1
workflows:
  - name: publish-merged-specs
    on:
      pull_request:
        types: [closed]
        base: [main]
        merged: true
        paths: ["docs/specs/**"]
    steps:
      - name: Record the merged specification
        shell: printf '%s\n' "The specification pull request was merged"
```

:::important Pull request từ fork không bao giờ chạy
BWV Workflows luôn bỏ qua pull request từ fork. Bạn không thể thay đổi cách hoạt động này bằng cấu hình.
:::

### 2. Cấu hình điều kiện kích hoạt từ push {#2-configure-a-push-trigger}

👤 Phụ trách: Project Leader

Dùng `on.push` cho công việc chạy theo một cập nhật trực tiếp vào một nhánh:

```yaml title=".bwv/workflows.yml"
version: 1
workflows:
  - name: check-published-specs
    on:
      push:
        branches: [main, "release/*"]
        paths: ["docs/specs/**"]
        ignorePaths: ["docs/specs/archive/**"]
    steps:
      - name: Check the published specifications
        shell: ./.bwv/scripts/check-specs.sh docs/specs
```

`branches` là bắt buộc và quyết định workflow có thể chạy hay không. `paths` và `ignorePaths` dùng cùng quy tắc khớp như pull request khi có danh sách file thay đổi đầy đủ.

:::caution Bộ lọc đường dẫn khi push chỉ có tính hướng dẫn
GitHub giới hạn danh sách commit trong dữ liệu của một lần push ở 20 mục. Khi BWV Workflows không biết được danh sách file đầy đủ, nó sẽ chạy workflow để tránh bỏ sót thay đổi. Hãy để các bước tự xác nhận có cần làm việc hay không.
:::

Lần chạy từ push thực thi nội dung repository ở commit vừa được push. Vì vậy, chỉ người được tin cậy để thay đổi tự động hóa mới nên được push lên nhánh khớp điều kiện.

### 3. Dùng cả hai khi cần {#3-use-both-triggers-when-needed}

👤 Phụ trách: Project Leader

Đặt `pull_request` và `push` trong cùng khối `on` khi một trong hai sự kiện đều cần bắt đầu cùng các bước:

```yaml title=".bwv/workflows.yml"
version: 1
workflows:
  - name: validate-specs
    on:
      pull_request:
        types: [opened, synchronize, reopened]
        base: [main]
        paths: ["docs/specs/**"]
      push:
        branches: [main]
        paths: ["docs/specs/**"]
    steps:
      - name: Validate the specifications
        shell: ./.bwv/scripts/check-specs.sh docs/specs
```

Bắt buộc phải có ít nhất một trong hai loại điều kiện kích hoạt. Khi có cả hai, mỗi sự kiện chỉ được so khớp với khối điều kiện của chính nó.

### 4. Merge thay đổi cấu hình trước khi kiểm tra {#4-merge-configuration-changes-before-testing}

👤 Phụ trách: Project Leader

Với lần chạy cho pull request, BWV Workflows đọc `.bwv/workflows.yml` và `.claude/` từ nhánh đích của pull request. Thay đổi trong chính pull request đó không điều khiển lần chạy. Hãy merge chúng vào nhánh đích, rồi mở hoặc cập nhật một pull request khác để kiểm tra.

Với lần chạy từ push, BWV Workflows đọc cấu hình từ commit được push trên nhánh đích. Vì vậy, điều kiện kích hoạt push mới bắt đầu có hiệu lực sau khi cấu hình đến được một nhánh khớp với `on.push.branches`.

Xem [Workflow đầu tiên của bạn](../getting-started/first-workflow) để biết đầy đủ quy trình merge và kiểm tra.
