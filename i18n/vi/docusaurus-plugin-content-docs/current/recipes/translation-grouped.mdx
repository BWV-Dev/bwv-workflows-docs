👤 Phụ trách: Project Leader

Dùng workflow recipe này cho repository đồng bộ Markdown tiếng Nhật qua một nhánh riêng rồi xuất bản bản dịch tiếng Việt đã review sang nhánh khác. Recipe gom file theo pull request nguồn, tạo một draft pull request bản dịch cho mỗi nhóm, rồi kiểm tra từng bản dịch và cache đã đầy đủ trước khi xuất bản.

Recipe cũng giữ file cache khớp với câu chữ mà người review sửa trên nhánh dịch. Pull request vào các nhánh kiểm soát đã cấu hình phải vượt qua bước kiểm tra cache.

## Nội dung người dùng thấy trên pull request

Trước khi pull request đồng bộ được merge, BWV Workflows thêm một comment theo dõi (tracker) dự kiến. Sau khi merge, cùng tracker đó hiển thị từng nhóm nguồn và PR được tạo cho nhóm. Dev & Com đọc tracker theo [Làm việc với BWV Workflows trên PR](../pull-requests).

Mỗi PR được tạo đều là draft. Dev & Com review Markdown tiếng Việt ở đó, rồi làm theo [Làm việc với BWV Workflows trên PR](../pull-requests). Project Leader dùng [Khi Dev & Com báo vấn đề](../troubleshooting/dev-com-reports) cho kết quả tracker ít gặp.

## Điều kiện cần có

Chuẩn bị repository đích trước khi thêm recipe:

- Giữ Markdown tiếng Nhật trong một thư mục nguồn tương đối với repository, chẳng hạn `docs/specs`.
- Chọn một thư mục đầu ra riêng có cùng cấu trúc cây, chẳng hạn `docs_vn/specs`.
- Thêm bảng thuật ngữ Markdown, chẳng hạn `docs/glossary.md`, chứa thuật ngữ và quy tắc dịch của dự án. Quy tắc dự án trong file này được ưu tiên hơn quy tắc chung của recipe.
- Dùng một nhánh đồng bộ, chẳng hạn `docs-sync`, rồi merge nhánh đó vào nhánh đích đồng bộ như `main` qua pull request.
- Bảo vệ nhánh đích đồng bộ và mọi nhánh kiểm soát để đầu ra đã review không thể bỏ qua các check bắt buộc.
- Nhờ BWV Workflows maintainers cho phép repository của bạn truy cập repository recipe chính thức.
- Không dùng khoảng trắng trong đường dẫn cấu hình và đường dẫn tài liệu. Recipe truyền các đường dẫn này thành những đối số command riêng.

## Thêm workflow

Tạo `.bwv/workflows.yml` trên nhánh đích:

```yaml
version: 1

workflows:
  - name: translate-specs
    uses: BWV-Dev/bwv-workflows-recipes/recipes/translation/grouped.yml@v1
    with:
      sourceRoot: docs/specs
      outputRoot: docs_vn/specs
      glossary: docs/glossary.md
      syncBase: main
      sourceBranch: docs-sync
      gateBases: [main, docs-sync]
      branchPrefix: bwv/translate
      model: sonnet
      maxFilesPerGroup: 3
```

Recipe tự quản lý các điều kiện kích hoạt và dùng toolkit mặc định khi bạn bỏ qua `toolkit`. Giữ tham chiếu chính thức `@v1` như ví dụ trên.

## Vấn đề thường gặp

### Không bắt đầu dịch sau khi merge

Kiểm tra pull request đã được merge từ `sourceBranch` vào `syncBase` và đã thay đổi file `.md` bên dưới `sourceRoot`. Chiều của nhánh rất quan trọng.

### Một nhóm thất bại vì thiếu đầu ra

Mở check run và xem file được nêu tên. Mỗi nguồn phải tạo cả bản dịch `.vi.md` có cùng cấu trúc và cache `.vi.json`. Sửa nguồn, bảng thuật ngữ hoặc toolkit tùy chỉnh, rồi hướng dẫn Dev & Com đọc [Làm việc với BWV Workflows trên PR](../pull-requests).

### Tracker báo một phần đầu ra đã nằm trên nhánh đích

Đừng chạy lại ngay. Trước tiên, xử lý các file đầu ra được liệt kê trên nhánh đích. Sau đó, dùng [Khi Dev & Com báo vấn đề](../troubleshooting/dev-com-reports) để chọn hành động tiếp theo.

### Check cache thất bại sau khi người review sửa

Kiểm tra chỉnh sửa đã được push lên nhánh bên dưới `branchPrefix`. Đọc kết quả check đồng bộ cache, sửa mọi lỗi được báo về cấu trúc tài liệu hoặc cache, rồi chạy lại sau khi nhánh đã được sửa.

### Đường dẫn đã cấu hình bị từ chối

Dùng đường dẫn tương đối với repository, không có khoảng trắng, đoạn `.` hoặc đoạn `..`. Xác nhận thư mục nguồn và bảng thuật ngữ tồn tại trên nhánh đích.
