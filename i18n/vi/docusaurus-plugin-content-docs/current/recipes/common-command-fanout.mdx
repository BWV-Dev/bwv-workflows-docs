👤 Phụ trách: Project Leader

Dùng step recipe này bên trong workflow hoặc recipe của dự án khi một bước trước trả về nhiều mục độc lập và cùng một skill hoặc command của dự án phải xử lý từng mục. Mỗi mục chạy trong tiến trình riêng. Chỉ dùng recipe này khi các mục ghi vào những file riêng biệt.

:::note
Đây là step recipe. Workflow gọi recipe quản lý điều kiện kích hoạt, bước lập kế hoạch, hành động khi thành công và PR kết quả.
:::

## Nội dung người dùng thấy trên pull request

Người dùng thấy check `bwv/<workflow>` và comment trạng thái của workflow gọi recipe. Bước fan-out hiển thị như một bước của workflow, còn các tiến trình cho từng mục chạy độc lập. PR kết quả, nếu có, do workflow gọi recipe tạo ra chứ không phải recipe này.

Hướng dẫn người review đọc [check run và comment trạng thái](../pull-requests/read-checks-status). Sau khi sửa một mục, dùng cách chạy lại được mô tả trong [Chạy lại một tác vụ](../pull-requests/retry).

## Điều kiện cần có

Chuẩn bị repository đích và workflow gọi recipe:

- Thêm bước lập kế hoạch trả về một mảng. Mỗi mục phải chứa dữ liệu cần để tạo đối số cho mục đó.
- Thêm skill của dự án tại `.claude/skills/<name>/SKILL.md` hoặc command tại `.claude/commands/<name>.md`.
- Để mỗi mục ghi vào file hoặc thư mục khác nhau. Các tiến trình dùng chung một cây làm việc và có thể chạy cùng lúc.
- Cấp cho mục chạy mọi công cụ nó cần và chặn rõ các đường dẫn nó không được sửa.
- Chọn giá trị `maxParallel` phù hợp với lượng công việc độc lập.
- Nhờ BWV Workflows maintainers cho phép repository của bạn truy cập repository recipe chính thức.

## Thêm workflow

Tạo `.bwv/workflows.yml` trên nhánh đích. Ví dụ sau gọi command `review-doc` của dự án cho hai tài liệu giả:

```yaml
version: 1

workflows:
  - name: review-specs
    on:
      pull_request:
        types: [opened, synchronize]
        base: [main]
        paths: ["docs/specs/**"]
    steps:
      - id: plan
        name: List documents to review
        shell: >-
          printf '%s\n' '{"files":[{"args":"docs/specs/login.md"},{"args":"docs/specs/profile.md"}]}'
        outputJson: true
      - id: review
        uses: BWV-Dev/bwv-workflows-recipes/recipes/common/command-fanout.yml@<sha-of-latest-tag>
        with:
          id: document
          items: ${{ steps.plan.output.files }}
          args: ${{ item.args }}
          model: sonnet
          maxTurns: 20
          allowedTools: ["Read", "Write", "Edit", "Glob"]
          disallowedTools: ["Edit(docs/specs/**)"]
          timeoutMinutes: 20
          maxParallel: 2
          toolkit:
            run: { command: review-doc }
```

Thay nội dung trả về cố định của bước lập kế hoạch bằng bộ lập kế hoạch của repository. Giữ `items` là một biểu thức lúc chạy duy nhất để nó trả về mảng thay vì văn bản.

### Lấy SHA của tag mới nhất

Thay `<tag>` bằng release tag mới nhất:

```bash
gh api repos/BWV-Dev/bwv-workflows-recipes/git/ref/tags/<tag> --jq '.object'
```

Nếu `type` trả về là `tag`, hãy mở tag có chú thích:

```bash
gh api repos/BWV-Dev/bwv-workflows-recipes/git/tags/<tag-object-sha> --jq '.object.sha'
```

Hoặc kiểm tra tag bằng Git:

```bash
recipe_url=$(gh repo view BWV-Dev/bwv-workflows-recipes --json url --jq '.url')
git ls-remote --tags "$recipe_url" \
  "refs/tags/<tag>" "refs/tags/<tag>^{}"
```

Dùng dòng `^{}` khi có; nếu không, dùng dòng của tag. SHA đầy đủ cố định phiên bản recipe đã review. `@v1` có thể di chuyển mà repository của bạn không có thay đổi nào.

## Vấn đề thường gặp

### Recipe bị từ chối ở cấp cao nhất của workflow

Đặt recipe bên dưới `steps` của workflow. `common/command-fanout` tạo ra các bước, không tạo workflow hoàn chỉnh.

### `items` bị coi là văn bản

Truyền một biểu thức lúc chạy đầy đủ, chẳng hạn `${{ steps.plan.output.files }}`. Biểu thức nằm trong văn bản sẽ bị chuyển thành văn bản và không thể cung cấp mảng mà `forEach` cần.

### Các tiến trình ghi đè lẫn nhau

Sửa bộ lập kế hoạch hoặc command để mỗi mục ghi vào đường dẫn riêng biệt. Giảm `maxParallel` có thể che đi việc trùng đường dẫn nhưng không đáp ứng hợp đồng của recipe.

### Thiếu mục chạy

Cung cấp `toolkit.run` dưới dạng skill hoặc command của dự án. Recipe này không có giá trị mặc định vì nó không biết dự án của bạn cần chạy gì.

### Một tiến trình không thể sửa hoặc đọc file cần thiết

Kiểm tra `allowedTools` và `disallowedTools`. Cùng một danh sách được dùng cho mọi mục. Vì vậy, hãy tách công việc thành các lần gọi riêng nếu các mục cần quyền khác nhau.
