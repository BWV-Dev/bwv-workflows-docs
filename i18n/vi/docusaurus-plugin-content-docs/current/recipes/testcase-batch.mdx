👤 Phụ trách: Project Leader

Dùng workflow recipe này khi các đặc tả `.vi.md` đã review là nguồn để tạo testcase. Với mỗi lần push khớp điều kiện, recipe tìm file testcase còn thiếu hoặc đã cũ, tạo một nhóm rồi mở một draft pull request. Sau đó, recipe lặp lại từ cây làm việc đã cập nhật cho đến khi hết việc tồn hoặc đạt `maxIterations`.

Tiến độ nằm trong các file đã commit và thông tin commit nguồn của chúng. Lần chạy sau có thể tiếp tục mà không cần con trỏ riêng.

## Nội dung người dùng thấy trên pull request

BWV Workflows mở một draft pull request cho mỗi nhóm. Mỗi pull request chỉ chứa file testcase của nhóm đó. Dev & Com review các testcase được tạo và mọi **TODO: to confirm** theo đặc tả đã review.

Đọc [check run và comment trạng thái](../pull-requests/read-checks-status) cho nhóm hiện tại. Dùng [Chạy lại một tác vụ](../pull-requests/retry) nếu việc tạo file thất bại sau khi nguồn hoặc cấu hình đã được sửa. Nếu PR kết quả bị đóng mà chưa merge, hãy làm theo [Tạo lại pull request đã đóng](../pull-requests/recreate).

## Điều kiện cần có

Chuẩn bị repository đích trước khi thêm recipe:

- Lưu các bản dịch đã review dưới dạng file `.vi.md` trong một thư mục nguồn, chẳng hạn `docs_vn/specs`.
- Chọn một thư mục đầu ra riêng có cùng cấu trúc, chẳng hạn `testcases/specs`.
- Bảo vệ từng nhánh nguồn đã cấu hình để chỉ bản dịch đã review mới kích hoạt việc tạo testcase.
- Dành riêng tiền tố nhánh đã cấu hình cho BWV Workflows. Recipe thêm một ID nhóm ổn định vào tiền tố đó.
- Không dùng khoảng trắng trong đường dẫn cấu hình và đường dẫn tài liệu.
- Nhờ BWV Workflows maintainers cho phép repository của bạn truy cập repository recipe chính thức.

## Thêm workflow

Tạo `.bwv/workflows.yml` trên nhánh đích:

```yaml
version: 1

workflows:
  - name: generate-testcases
    uses: BWV-Dev/bwv-workflows-recipes/recipes/testcase/batch.yml@<sha-of-latest-tag>
    with:
      sourceRoot: docs_vn/specs
      outputRoot: testcases/specs
      branches: [main]
      branchPrefix: bwv/testcases
      model: sonnet
      maxIterations: 10
```

Recipe dùng bộ lập kế hoạch và skill tạo testcase do BWV Workflows maintainers chăm sóc khi bạn bỏ qua `toolkit`. Bộ lập kế hoạch mặc định lấy một file đang chờ cho mỗi nhóm. `maxIterations` giới hạn số lượt, không giới hạn số file trong một nhóm.

### Lấy SHA của tag mới nhất

Thay `<tag>` bằng release tag mới nhất:

```bash
gh api repos/BWV-Dev/bwv-workflows-recipes/git/ref/tags/<tag> --jq '.object'
```

Nếu `type` trả về là `tag`, hãy mở tag có chú thích:

```bash
gh api repos/BWV-Dev/bwv-workflows-recipes/git/tags/<tag-object-sha> --jq '.object.sha'
```

Hoặc kiểm tra tag bằng Git:

```bash
recipe_url=$(gh repo view BWV-Dev/bwv-workflows-recipes --json url --jq '.url')
git ls-remote --tags "$recipe_url" \
  "refs/tags/<tag>" "refs/tags/<tag>^{}"
```

Dùng dòng `^{}` khi có; nếu không, dùng dòng của tag. SHA đầy đủ cố định phiên bản recipe đã review. `@v1` có thể di chuyển mà repository của bạn không có thay đổi nào.

## Vấn đề thường gặp

### Thay đổi bản dịch không bắt đầu lần chạy

Xác nhận lần push đã đến một trong các `branches` và làm thay đổi file `.vi.md` bên dưới `sourceRoot`.

### Cùng một nguồn vẫn nằm trong danh sách chờ

File testcase được tạo phải kết thúc bằng thông tin nguồn chứa đầy đủ commit thay đổi bản dịch gần nhất. Hãy sửa công cụ tạo file tùy chỉnh nếu công cụ bỏ qua hoặc thay đổi phần cuối này.

### Vẫn còn nhiều việc sau khi lần chạy thành công

Lần chạy dừng ở `maxIterations`. Review các pull request đã mở, rồi bắt đầu lần chạy khác hoặc tăng giới hạn nhưng không vượt quá giá trị tối đa trong phần tham khảo được tạo tự động.

### Không thể cập nhật nhánh của nhóm

BWV Workflows không ghi đè nhánh của nhóm sau khi tác giả khác thay đổi commit đầu nhánh. Hãy giữ lại commit của người đó, chọn `branchPrefix` khác hoặc xử lý nhánh trước khi chạy lại.

### Hai file tạo ra cùng một ID nhóm

Đổi tên một đường dẫn nguồn để mỗi file đang chờ tạo ra ID nhánh riêng. Bộ lập kế hoạch từ chối trường hợp trùng thay vì để một nhóm ghi đè nhóm khác.
