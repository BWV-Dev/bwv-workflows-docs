Thêm một workflow nhỏ chạy trên pull request để xác nhận việc đưa repository vào sử dụng, bảo vệ nhánh (branch protection), chạy workflow và xuất bản kết quả đều hoạt động.

## Hướng dẫn từng bước

### 1. Thêm file workflow

👤 Phụ trách: Project Leader

Tạo `.bwv/workflows.yml` với cấu hình sau. Thay `main` nếu repository dùng một nhánh đích (base branch) được bảo vệ khác.

```yaml title=".bwv/workflows.yml"
version: 1
workflows:
  - name: first-workflow
    on:
      pull_request:
        types: [opened, synchronize, reopened]
        base: [main]
    steps:
      - name: Write a change summary
        claude:
          prompt: |
            Read the pull request diff.
            Create or update docs/workflow-summary.md with a short summary.
            Do not change any other file.
          allowedTools: [Read, Write, Edit, "Bash(git diff:*)"]
    onSuccess:
      createPullRequest:
        branch: "bwv/first-workflow/pr-${{ pr.number }}"
        title: "docs: add workflow summary"
      comment: false
```

Workflow này chạy một bước Claude cho pull request nhắm vào `main`. Khi bước đó thay đổi `docs/workflow-summary.md`, BWV Workflows sẽ mở một PR kết quả.

### 2. Merge cấu hình vào nhánh đích

👤 Phụ trách: Project Leader

Commit file trên một nhánh thiết lập:

```bash
git switch -c chore/add-bwv-workflow main
git add .bwv/workflows.yml
git commit -m "chore: add first BWV workflow"
git push --set-upstream origin chore/add-bwv-workflow
gh pr create --base main --title "chore: add first BWV workflow" --body "Add the initial BWV Workflows configuration."
```

Review và merge pull request thiết lập này theo quy tắc bảo vệ nhánh. Workflow chưa áp dụng cho chính pull request thiết lập vì cấu hình được lấy từ nhánh đích.

:::important Merge trước khi thử nghiệm
Workflow phải có trên `main` trước khi một pull request thử nghiệm riêng có thể dùng workflow. Thay đổi với `.bwv/workflows.yml` chỉ có hiệu lực sau khi được merge.
:::

### 3. Mở một pull request thử nghiệm

👤 Phụ trách: Project Leader

Cập nhật nhánh đích cục bộ, tạo một nhánh thử nghiệm rồi sửa một tài liệu không quan trọng, ví dụ `docs/specs/login.md`:

```bash
git switch main
git pull --ff-only
git switch -c docs/test-first-workflow
# Edit docs/specs/login.md, then continue.
git add docs/specs/login.md
git commit -m "docs: test BWV workflow"
git push --set-upstream origin docs/test-first-workflow
gh pr create --base main --title "docs: test BWV workflow" --body "Verify the first BWV workflow."
```

Không merge pull request thử nghiệm trước khi lần chạy hoàn tất.

### 4. Kiểm tra lần chạy

👤 Phụ trách: Project Leader

Bạn sẽ thấy các kết quả sau:

1. Một check tên `bwv/first-workflow` bắt đầu trên pull request thử nghiệm.
2. Một comment trạng thái của **BWV Workflows** được cập nhật khi bước chạy.
3. Check thành công sau khi bước hoàn tất.
4. Nếu `docs/workflow-summary.md` thay đổi, comment đặt liên kết đến PR kết quả tên **docs: add workflow summary**.

### 5. Đọc một lần thất bại

👤 Phụ trách: Project Leader

1. Mở check `bwv/first-workflow` đã thất bại.
2. Tìm bước thất bại đầu tiên và đọc lỗi.
3. Mở rộng khối nội dung trả về để xem phần cuối nội dung trả về của bước Claude.
4. Kiểm tra comment trạng thái của cùng workflow.
5. Sửa cấu hình trên nhánh đích nếu lỗi nằm trong `.bwv/workflows.yml`.

Xem [Đọc check run và comment trạng thái](../pull-requests/read-checks-status) để hiểu toàn bộ bố cục báo cáo. Xem [Khắc phục sự cố và câu hỏi thường gặp](../troubleshooting) nếu lỗi không chỉ ra cách sửa.
